# elif and Nested Conditions

`if` and `else` give only two options. What if there are more possibilities, like the letter
grades A, B, C, D? That's what `elif` (short for *else if*) is for.

<Playground initialCode={`score = int(input("Exam score (0-100): "))

if score >= 85:
    print("Grade: A")
elif score >= 70:
    print("Grade: B")
elif score >= 55:
    print("Grade: C")
else:
    print("Grade: D")`} />

## Order matters

Python checks the conditions **from top to bottom** and **stops at the first one that is
`True`**. The rest are skipped.

With a score of `90`, the condition `score >= 70` is also true, but it's never checked, because
`score >= 85` already matched.

See what happens when the order is reversed:

<Playground initialCode={`score = 90

if score >= 55:
    print("C")
elif score >= 70:
    print("B")
elif score >= 85:
    print("A")`} />

The result is `C`, when it should be `A`. The program runs without an error, but the logic is
wrong.

<Callout type="tip">
  When using `>=`, order the conditions from the **largest** number to the smallest.
</Callout>

## else is optional

The final `else` can be left out. If no condition is `True` and there's no `else`, no block runs.

## if inside if

An `if` block can contain another `if`. Notice the extra indentation:

<Playground initialCode={`age = 20
has_ticket = True

if age >= 17:
    if has_ticket:
        print("Please come in")
    else:
        print("Buy a ticket at the counter first")
else:
    print("Sorry, 17 and over only")`} />

Nested `if`s can often be simplified with `and`, but the form above is useful when each case
needs a different message.

## Summary

- `elif` adds another condition after `if`.
- Python stops at the first `True` condition, so the order of conditions decides the result.
- The final `else` is optional.
- An `if` can sit inside another `if`, with extra indentation.
