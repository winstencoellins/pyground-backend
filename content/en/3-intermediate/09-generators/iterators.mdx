# Meet Iterators

You have often used `for` with lists, strings, dicts, `range()`, and even files. But how can
one `for` statement work for all of those kinds of data? The answer is the **iterator**.

## Iterables and iterators

These two terms sound alike, but they are different:

- An **iterable** is something that **can** be walked through one item at a time: lists,
  tuples, strings, dicts, sets, `range`, files.
- An **iterator** is a "pointer" moving along an iterable that knows the **next** item.

The `iter()` function makes an iterator from an iterable, and `next()` fetches the next
item:

<Playground initialCode={`queue = ["Budi", "Ani", "Citra"]

pointer = iter(queue)
print(type(queue))
print(type(pointer))

print(next(pointer))
print(next(pointer))
print(next(pointer))`} />

Think of the list as a book, and the iterator as a bookmark marking the last page you read.

## When it runs out: `StopIteration`

An iterator can only move forward. Once it is used up and you call `next()` again, Python
raises `StopIteration`:

<Playground expectError initialCode={`queue = ["Budi", "Ani"]
pointer = iter(queue)

print(next(pointer))
print(next(pointer))
print(next(pointer))`} />

A used-up iterator cannot be restarted. To start over, create a new iterator with `iter()`
again. You can also give `next()` a fallback value so it does not raise an error:

<Playground initialCode={`pointer = iter([10, 20])
print(next(pointer, "done"))
print(next(pointer, "done"))
print(next(pointer, "done"))`} />

## How `for` works under the hood

Every time you write `for`, Python actually does this: it calls `iter()` once, then calls
`next()` again and again until it hits `StopIteration`, and then stops quietly. We can
imitate it with `while` and `try`/`except`:

<Playground initialCode={`menu = ["soto", "bakso", "gado-gado"]

# The usual version
for food in menu:
    print(food)

print()

# What Python really does
pointer = iter(menu)
while True:
    try:
        food = next(pointer)
    except StopIteration:
        break
    print(food)`} />

<Callout type="info">
  That is why `for` works on anything iterable. As long as an object can be passed to
  `iter()`, `for` can walk through it.
</Callout>

## Iterators over dicts, ranges, and files

Each kind of iterable decides for itself what its iterator produces:

<Playground initialCode={`prices = {"tea": 3000, "coffee": 5000}
it = iter(prices)
print(next(it))          # a dict produces its keys

it_items = iter(prices.items())
print(next(it_items))    # .items() produces (key, value) pairs

it_range = iter(range(0, 10, 3))
print(next(it_range), next(it_range))

with open("attendance.txt", "w") as f:
    f.write("Budi")
    f.write(chr(10))
    f.write("Ani")
    f.write(chr(10))

with open("attendance.txt") as f:
    print(next(f).strip())  # a file produces one line at a time
    for line in f:
        print("Next:", line.strip())`} />

Look at the file example: after `next(f)` takes the first line, the `for` loop continues
from the second line, because both use the same iterator. `chr(10)` is the newline
character.

## Summary

- An iterable can be walked through item by item; an iterator is a pointer that knows the next item.
- `iter()` makes an iterator, `next()` fetches the next item.
- A used-up iterator raises `StopIteration` and cannot be restarted.
- Under the hood, `for` calls `iter()` once and then `next()` until `StopIteration`.
