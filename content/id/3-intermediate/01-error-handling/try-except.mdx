# Menangani Error dengan `try`/`except`

Program yang baik tidak langsung "meledak" ketika pengguna mengetik sesuatu yang aneh.
Coba jalankan kode ini:

<Playground initialCode={`umur = int("dua puluh")
print(umur)`} />

Python menampilkan `ValueError`, lalu program berhenti. Error seperti ini disebut **exception**.

## Menangkap exception

<Playground initialCode={`teks = "dua puluh"
try:
    umur = int(teks)
    print("Umurmu", umur)
except ValueError:
    print("Masukkan umur dalam bentuk angka, ya!")`} />

<AnimatedDiagram name="try-except-flow" caption="Jika baris di dalam try gagal, Python melompat ke except yang cocok." />

## `else` dan `finally`

- `else` berjalan **hanya jika** tidak ada error.
- `finally` **selalu** berjalan, cocok untuk "beres-beres" seperti menutup file.

<Playground initialCode={`def bagi(a, b):
    try:
        hasil = a / b
    except ZeroDivisionError:
        print("Tidak bisa membagi dengan nol")
    else:
        print("Hasil:", hasil)
    finally:
        print("Selesai menghitung")

bagi(10, 2)
bagi(10, 0)`} />

<Callout type="warning">
  Hindari `except:` tanpa nama exception. Itu akan menangkap **semua** error, termasuk bug di
  kodemu sendiri, sehingga lebih sulit di-debug.
</Callout>

<Callout type="tip">
  Tangkap exception yang spesifik (`ValueError`, `KeyError`, `FileNotFoundError`) dan simpan
  pesannya dengan `except ValueError as e:` lalu `print(e)`.
</Callout>

## Membuat exception sendiri

Kamu juga bisa memunculkan error dengan `raise` ketika data tidak masuk akal:

<Playground initialCode={`def set_umur(umur):
    if umur < 0:
        raise ValueError("Umur tidak boleh negatif")
    return umur

try:
    set_umur(-5)
except ValueError as e:
    print("Error:", e)`} />

## Ringkasan

- `try` membungkus kode yang mungkin gagal; `except` menanganinya.
- `else` untuk jalur sukses, `finally` untuk yang selalu dijalankan.
- Tangkap exception spesifik dan gunakan `raise` untuk data yang tidak valid.
