# Method Spesial

Kamu sudah kenal `__init__`. Python punya banyak method lain dengan dua garis bawah di depan
dan belakang namanya, sering disebut **dunder method** (*double underscore*). Python
memanggilnya otomatis saat kamu memakai `print()`, `==`, `len()`, atau `+` pada object-mu.

## `__str__`: tampilan untuk manusia

Coba cetak sebuah object biasa. Hasilnya kurang berguna.

<Playground initialCode={`class Rupiah:
    def __init__(self, jumlah):
        self.jumlah = jumlah

harga = Rupiah(15000)
print(harga)`} />

`print()` memanggil `str()` pada object, dan `str()` mencari method `__str__`. Kalau kamu
menulisnya, kamu yang menentukan tampilannya.

<Playground initialCode={`class Rupiah:
    def __init__(self, jumlah):
        self.jumlah = jumlah

    def __str__(self):
        return f"Rp{self.jumlah:,}".replace(",", ".")

harga = Rupiah(15000)
print(harga)
print("Harga nasi padang:", harga)
teks = str(Rupiah(2500000))
print(teks)`} />

`__str__` harus **mengembalikan** string dengan `return`, bukan mencetaknya.

## `__repr__`: tampilan untuk programmer

`__repr__` dipakai saat object ditampilkan untuk keperluan debugging, misalnya saat object
berada di dalam list. Biasanya bentuknya mirip kode untuk membuat object itu.

<Playground initialCode={`class Rupiah:
    def __init__(self, jumlah):
        self.jumlah = jumlah

    def __str__(self):
        return f"Rp{self.jumlah:,}".replace(",", ".")

    def __repr__(self):
        return f"Rupiah({self.jumlah})"

daftar_harga = [Rupiah(5000), Rupiah(12000)]
print(daftar_harga)
print(daftar_harga[0])
print(repr(daftar_harga[0]))`} />

<Callout type="tip">
  Kalau kamu hanya sempat menulis satu, tulis `__repr__`. Saat `__str__` tidak ada, `print()`
  akan memakai `__repr__` sebagai gantinya.
</Callout>

## `__eq__`: membandingkan dengan `==`

Secara bawaan, `==` pada object hanya bernilai `True` kalau keduanya object yang *sama persis*.
Dua uang Rp5.000 terpisah dianggap berbeda. `__eq__` mengubah aturan itu.

<Playground initialCode={`class Rupiah:
    def __init__(self, jumlah):
        self.jumlah = jumlah

print("Tanpa __eq__:", Rupiah(5000) == Rupiah(5000))

class Rupiah:
    def __init__(self, jumlah):
        self.jumlah = jumlah

    def __eq__(self, lain):
        return self.jumlah == lain.jumlah

print("Dengan __eq__:", Rupiah(5000) == Rupiah(5000))
print(Rupiah(5000) == Rupiah(2000))`} />

## `__len__` dan `__add__`

`__len__` dipanggil oleh `len()`, dan `__add__` dipanggil oleh operator `+`. Contohnya keranjang
belanja di warung.

<Playground initialCode={`class Keranjang:
    def __init__(self, barang=None):
        if barang is None:
            barang = []
        self.barang = barang

    def tambah(self, nama):
        self.barang.append(nama)

    def __len__(self):
        return len(self.barang)

    def __add__(self, lain):
        return Keranjang(self.barang + lain.barang)

    def __str__(self):
        return "Keranjang: " + ", ".join(self.barang)

punya_budi = Keranjang()
punya_budi.tambah("Kopi")
punya_budi.tambah("Gula")

punya_ani = Keranjang(["Teh", "Roti"])

gabungan = punya_budi + punya_ani
print(gabungan)
print("Jumlah barang:", len(gabungan))
print(len(punya_budi))`} />

`__add__` mengembalikan object **baru**, jadi keranjang Budi dan Ani tidak berubah. Ini sama
seperti `1 + 2` yang tidak mengubah angka 1.

Perhatikan `barang=None` di `__init__`: kalau kita menulis `barang=[]`, semua keranjang yang
dibuat tanpa argumen akan memakai list yang sama, mirip jebakan atribut class yang sudah kamu
pelajari.

## Menggabungkan semuanya

<Playground initialCode={`class Rupiah:

## Ringkasan

- Method spesial (dunder) dipanggil otomatis oleh Python, bukan oleh kamu langsung.
- `__str__` untuk `print()` dan `str()`; `__repr__` untuk tampilan debugging dan isi list.
- `__eq__` mengatur `==`, `__len__` mengatur `len()`, dan `__add__` mengatur `+`.
- Method spesial harus mengembalikan nilai dengan `return`; `__add__` sebaiknya mengembalikan object baru.
